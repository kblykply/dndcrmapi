# ISO 2026 module

The separate `/iso-2026` workspace uses the supplied **ISO 9001:2026(en)** PDF
(sixth edition, September 2026). `/quality-control` and its existing records
remain unchanged. The new menu item appears next to Quality Control.

## Source content

- `src/iso-2026/iso-2026-source.json` contains 173 clauses/headings, including
  the introduction, terms, numbered paragraphs, Annex A and bibliography.
- English source wording is retained. Only running headers, licence watermarks,
  footers and whitespace are removed from the reading view. Turkish titles are
  navigation translations; the requirement text is English.
- Numbered paragraphs without their own heading inherit their parent title and
  are marked `titleIsEditorial`; their full source sentence remains in `body`.
- The extraction script orders PDF spans by their baseline and reconciles every
  source token with the clause output. Page references use actual PDF page numbers
  (printed page 1 is PDF page 11).
- Re-extraction: run `scripts/extract-iso2026.py /path/to/source.pdf` with PyMuPDF
  available in a separate tooling environment. The script checks the edition
  structure and produces a SHA-256 fingerprint.
- The original file is stored at
  `project-documents/iso-2026/ISO_9001_2026.pdf`. Keep this private asset with the
  API deployment. It is not a frontend public asset.
- `nest build` copies the catalogue into `dist/src/iso-2026`; the protected
  `/iso-2026/source/pdf` endpoint streams the original file after authorization.

## Workspace and access

`ADMIN`, `MANAGER`, `AFTERSALES` and `SALES` can read and edit. `PREVIEW` can
only read. Both JSON and PDF endpoints require the existing JWT and role guards.

`Iso2026Card`, `Iso2026ChecklistItem`, `Iso2026Document` and `Iso2026Log` are
independent of the old quality tables. The additive migration is
`20260925120000_add_iso_2026`. All four tables use row-level security without
direct-client policies, consistent with other API-only CRM modules.

GET requests do not seed or modify records. A working card is created on its
first edit. Source clause codes and text cannot be edited through workspace
endpoints. Card changes, checklist operations, document metadata and notes are
saved transactionally with an audit log. Document entries store a URL and
metadata, matching the existing quality module's document workflow.
Checklist due dates are calendar dates. The overview and details count an
unchecked item as overdue only after that date in the Asia/Famagusta time zone.

## Navigation and figures

The overview contains searchable clause titles and numbers, chapter filters,
the PDCA figure and the single-process figure. Diagram areas open actual clause
detail routes. Links assigned to process elements are application navigation
relationships, not additional requirements from the standard.

Clause details provide source text, PDF page references, parent/child and
related-clause links, previous/next navigation, editable working information,
checklists, documents and notes/history. Figures also appear with clauses 0.3.1
and 0.3.2. Workspace progress measures completed user checks, not certification
or compliance with the standard.
